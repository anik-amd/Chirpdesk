# Phase 6 — Ship

**Status:** in progress (2026-11-17). Tasks 1 and 6 are complete. `UpdateManifest`, deterministic
canonical bytes and `UpdateVerifier` cover https, stable channel, strictly-newer version, ECDSA
P-256 signature and payload size/hash; 18 unit tests use generated keys and fixtures. The
`--selftest` adds an `update-policy` check (signed accepted, tampered/older/wrong-key refused) and
never runs the app's update path. Task 2's release tooling is in `scripts/new-update-key.ps1` and
`scripts/sign-update.ps1`; the scripts sign with the same canonical bytes and verify the written
manifest before exiting. The first-run overlay is `Onboarding/OnboardingPage`, shown only when no
settings file exists and never from autostart/diagnostics; Got it and Esc return to hidden-warm.
The pinned public key, the check/apply path, installer, portable zip and CI are still open.
**ADR:** 0006 (signed self-update), 0009 (toast activation), 0012 (autostart)
**Plan:** `PLAN.md` §14, phase 6 row in §15

## Goal

A fresh machine can install Chirpdesk, and an installed copy can move to a newer signed release
without ever running an unverified installer. Portable builds never self-update.

## Tasks

1. **Update verification core** (`Chirpdesk.Core/Updates`)
   - `UpdateManifest`: version, stable channel, https URL, size, SHA-256, ECDSA P-256 signature.
   - Canonical manifest bytes exclude the signature and are deterministic.
   - Refuse a malformed signature, a wrong key, a non-https URL, a non-stable channel, a version
     that is not newer than the running build, and a payload whose hash or size differs.
   - Every refusal carries a reason for the log; nothing throws at the caller.
   - Unit tests use generated keys and fixtures. The app's real update path is never run in tests
     (invariant 7).
2. **Pinned key and release tooling**
   - Public key as SPKI PEM pinned in the app; private key stays off-repo.
   - A signing note in `docs/updates.md` with the exact canonical JSON and P1363 signature format.
   - A build with no key refuses every update instead of trusting one.
3. **Update check and apply**
   - GitHub Releases, stable channel only, opt-in; no check when disabled.
   - Download to `%APPDATA%\Chirpdesk\updates\`, verify, then dispose every WebView2 environment
     and exit before the silent installer runs. Relaunch on success.
   - Remove the downloaded files after apply; refuse and delete on any mismatch.
4. **Installer**
   - Inno Setup, per-user, no elevation, .NET 8 Desktop and WebView2 Evergreen checks.
   - Optional elevation through the signed Microsoft bootstrapper for the .NET runtime.
   - AUMID shortcut created on install; uninstall offers data deletion (default off, Recycle Bin).
5. **Portable zip and CI**
   - One Windows workflow: build, tests, pack installer + zip, attach to a GitHub Release.
6. **First run**
   - One overlay teaching the tray, `Ctrl+K` and the plugin page; dismissible and shown once.
7. **Definition**
   - README install/update/privacy notes, SmartScreen explanation, key rotation procedure.

## Definition of done (PLAN §15)

A fresh machine with neither runtime gets an honest prerequisite step and then a working app.
A second signed release updates itself; a tampered or older manifest is refused with the current
version still running.
